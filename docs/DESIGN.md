# 设计想法

> 记录这座岛「为什么长这样」：从三个硬约束出发，到一套能自我一致的配色与光照规则。

---

## 一、三个约束先于一切

动手之前先定死了三条，后面所有取舍都从这三条推出来：

1. **背景必须是透明的。** 它要挂在桌面上，桌面壁纸是未知的，所以不能有天空盒、不能有地面、不能有卡片阴影把画面框住。岛必须自己站得住。
2. **它是「摆件」，不是「场景」。** 视角永远停在岛外、略带俯视，不能进入岛内。物件的尺度关系要像沙盘模型，而不是像游戏关卡。
3. **它在动，但动的不是镜头。** 相机基本静止，靠风、水、粒子、人物、钟点来制造「活着」的感觉。任何大幅运镜都会破坏「摆在桌上」的心理定位。

第 1 条直接决定了雾的用法：常规做法是用雾把远处推淡，但这里远处就是桌面，雾只能用来做微弱的空气感，且强度必须跟着相机距离缩放（否则一缩放岛就"洗白"）。第 3 条决定了相机的默认姿态：正视、30° 透视、轻微俯角。

## 二、风格：写实微缩沙盘

参考的是一类桌面微缩景观照片——真实材质、真实光影、不描边、不卡通化。

具体落到实现上的几条：

- **颜色不靠饱和度取胜。** 树冠不用纯 `#00FF00`，用带灰的 `#4F9C31 / #357D25 / #6FB53F / #2A6B26` 四色混合，靠明暗层次而不是纯度表现体积。
- **必须有体积阴影。** 每个树冠都投 `castShadow`，但**树冠之间不互相接收阴影**——稠密树林里互相压黑，透亮感会立刻消失。这是刻意违反物理的一步。
- **岛的侧面必须有信息。** 大多数漂浮岛只做正面，一转就露馅。所以岩基做了分层岩层皮肤、垂根、冰柱、悬浮碎石，让侧视和背视都有内容。
- **不用后处理。** 没有 bloom、没有 SSAO、没有景深。所有氛围靠光照参数和材质本身完成。这样单文件打包体积小，低端机也不至于掉帧。

## 三、四季不是四套模型

这是整个项目最关键的一个决定。

一开始最容易想到的做法是「春=樱花树模型，夏=绿树模型，秋=枫树模型」，结果是四套几何、四套材质、四套 LOD，切换时还会穿模。

实际做法是：**一套几何 + 一个调色板 + 一组 0–1 权重**。

```js
// src/seasons.js
{
  grass:     [C('#93C64B'), C('#5D9433')],  // 草地亮/暗
  moss:      C('#86BB46'),
  dirt:      C('#8A7350'),
  rock:      [C('#A3917A'), C('#7B6E5D')],
  canopy:    [C('#F79AB8'), C('#FBCADD'), C('#EE7CA2'), C('#8FCB55')], // 树冠四色
  conifer:   [C('#37603A'), C('#4A7549')],
  water:     C('#5FBBDA'),
  waterRough: 0.10,
  snow:      0,   // 雪权重：草→白、树冠→白、水→冰
  flowers:   0.40, // 花甸密度
  folk:      0,    // 夏天的人物
  play:      0,    // 冬天的雪上活动
  sitters:   0,    // 秋天的两个人
  jizo:      0,    // 地藏
}
```

四季的字段结构**完全同构**，所以可以直接 `lerp`：

```js
mixPalette(秋, 冬, 0.4, out);  // 每一项逐字段插值，权重也一起插
```

这带来几个直接好处：

- 换季是真的「渐变」，不是淡入淡出叠两张图；
- 新增一个季节元素，只需要在四套调色板里各加一个权重字段；
- 雪的过渡是自然的：`snow` 从 0 插到 1 的过程中，草地先泛白、树冠先挂雪、水面先结冰，顺序由各自的着色公式决定。

权重字段怎么用？物体一直存在，每帧只改可见性和位置：

```js
// life.js
const w = { flowers: 0, folk: 0, dogsA: 0, dogsW: 0, play: 0, sitters: 0, jizo: 0 };
```

`w` 每帧向 `pal` 的目标值缓动，人物站起来的动作、花的长出、雪的堆积，都由这个 0–1 的连续量驱动，所以「切换」过程中人物不会突然出现或消失。

## 四、四季语义

每个季节要有一个**能被一眼认出**的符号，而不是四张不同绿色的图：

| 季节 | 符号 | 做法 |
|---|---|---|
| 春 | 樱花 + 飘落 | 树冠粉白四色；花瓣粒子倾角大、下落慢，像被风托着 |
| 夏 | 饱和的绿 + 人气 | 草最亮最绿；花甸开满；河边钓鱼的孩子、野餐看书的孩子、两只狗 |
| 秋 | 金红 + 静止 | 枫树冠橙红；落叶铺地；两个人坐在垫子上看枫叶（会抬头、指点、端茶） |
| 冬 | 雪 + 灯火 | 雪覆盖草地/树冠/屋顶；冰柱；雪洞；树上挑杆灯笼 |

秋天刻意选择「静止感」——不是狂欢，是坐着看叶子。冬天刻意选择「暖」——外面冷，灯火暖，这是冬天的情绪核心。

## 五、光照：三时段当成三套参数

最初的实现是「一个太阳 + 夜里调暗」，结果清晨和正午几乎没有区别，夜晚也只是一张压暗的白天。

后来改成三套独立预设，结构一致，按小时权重混合：

```js
morning: {
  keyCol: '#FFB06A', keyInt: 3.06, keyDir: [-0.82, 0.07, 0.56],
  exposure: 0.902, hemiInt: 0.114, env: 0.228,
  fogNear: 0.64, fogFar: 1.92, ambient: 0.01, rim: 0.397, lamp: 0,
}
```

三档的关键差异，其实是三件事：

1. **主光的角度。** 清晨 `y = 0.07`（仰角约 4°）、正午 `y = 0.88`（约 56°）、夜晚从背面偏左来（`z = -0.54`）。角度决定影子长度，影子长度决定时间感。
2. **雾的距离。** 清晨 `near 0.64 / far 1.92`（相对相机距离），正午 `1.06 / 2.98`。清晨空气"厚"，正午通透。
3. **曝光。** 正午 1.165、清晨 0.9、夜晚 0.5 上下。夜晚不能靠"调暗"实现，必须先降曝光，再让灯笼作为**独立光源**把局部提回来，层次才出得来。

权重混合用三次平滑（`smoothstep`）在边界前后各 0.6 小时过渡，三条权重归一化到 1：

```js
function periodWeights(hour) {
  const toNoon    = sstep(11 - f, 11 + f, h);
  const toNight   = sstep(17 - f, 17 + f, h);
  const fromNight = sstep(6  - f, 6  + f, h);
  const morning = fromNight * (1 - toNoon);
  const noon    = toNoon * (1 - toNight);
  const night   = Math.max(0, 1 - fromNight + fromNight * toNight);
  // 归一化后返回
}
```

于是 10:40 打开电脑，会看到清晨正在慢慢变成正午，而不是 11:00 整一跳。

## 六、夜晚：三层灯火

夜里的光要分层，否则要么全黑要么全亮。实际是三层：

**第一层 · 环境灯串**（`lantern.js`）
树间拉起绳索，串小灯泡，挂几只带肋骨的纸提灯。地面用加色贴片伪造"光池"，而不是每盏灯一个 `PointLight`——后者会把光照计算直接打爆。整片灯串只用 3 个真实点光做顶部氛围。

**第二层 · 建筑提灯**（`lantern.js`）
神社石灯笼的火袋、鸟居笠木下的提灯。它们是"锚点"，把灯串的视觉高度定住。

**第三层 · 季节装置**（`winterlights.js`）
冬天专属：竹竿从树干斜挑出去、杆头垂一盏纸灯，从左侧到右侧沿树群连成一条暖光走线，再加两座雪洞。这层只在冬天出现，靠 `winterLights` 权重控制。

三层都由同一个 `lamp` 值（0 白天 → 1 全夜）驱动，且**四季有不同的灯色**：

| 季 | lampTint | 倾向 |
|---|---|---|
| 春 | `#FFD9C4` | 偏粉 |
| 夏 | `#E8E2A8` | 偏青黄 |
| 秋 | `#FFB35C` | 金橙 |
| 冬 | `#FFA96A` | 暖橙 |

这样四季的夜不是同一张图换个树色，而是"同一个地方在四个季节的四个晚上"。

## 七、体积感从哪来

没有 SSAO 的情况下，靠四件东西堆体积：

1. **顶点色明暗。** 树冠的每个叶簇按「高度（下暗上亮）× 朝向主光的法线（受光面亮）」刷一层亮度顶点色，再把整体平均亮度归一化到 1，避免把树冠整体压暗。草地同理，用 fbm 噪声做斑块。
2. **影棚环境光。** 用一张程序化的渐变球做 PMREM 环境贴图，顶部亮、底部灰，让所有材质都有柔和的上下渐变。
3. **底部反弹光。** 一盏从下往上的方向光，专门照亮岛底，避免石底死黑。
4. **接触阴影。** 岛下方一张径向渐变贴片，让它在桌面上"落"下去，而不是飘着。

雾的距离始终乘以相机距离：

```js
scene.fog.near = radius * fogScale.near;
scene.fog.far  = radius * fogScale.far;
```

否则滚轮一放大，岛就被雾洗淡了——这是最早踩到的坑之一。

## 八、让它「活」：动的东西清单

| 对象 | 节奏 | 实现 |
|---|---|---|
| 岛体自转 | 静止 2.6s 后缓慢起转，0.12 rad/s | 拖拽时接管，松手衰减 |
| 溪水 | UV 双轴滚动，速度不同 | `waterMap.offset` |
| 跌水白练 | 快速向下滚动 | 单独贴图 offset |
| 花瓣/落叶/雪 | 随风偏移 + 自转 | GPU 点精灵 + 每帧相位 |
| 鸟群 | 绕岛盘旋，翅膀扇动 | 顶点动画，5 只 |
| 鱼 | 水下环游 | 路径偏移 |
| 人物 | 呼吸、抬手、端杯 | 关节 sin 叠加，周期错开 |
| 灯笼 | 轻微摆动 | 摆角 `sin(t * freq + phase)` |
| 悬空碎石 | 上下浮动 + 自转 | 每块相位不同 |

节奏刻意错开：没有两个东西共用同一个周期，所以画面永远不"同步闪一下"。

## 九、几次失败的尝试（都是真踩过的）

留在文档里，比只写结论有用：

**① 树越加越好看 → 加过头。**
为了让岛"丰盛"，把成簇数量从 22 加到 34、随机补植加到 200，结果是互相遮挡、鸟居被埋、草地全被吃掉。最后退回 22 簇 + 120 次随机 + 定点补植，并给鸟居画了一条**视线走廊**，走廊内长不出树。结论：**留白是构图的一部分，不是空缺。**

**② 灯笼做得像纸盒。**
第一版是收口鼓腹的旋转体，白天看还行，夜里像挂了一排橙色彩纸。换成**正圆球体 + 上下小深色盖**之后立刻成立——现实里的和风灯笼就是干净球体，多余造型反而廉价。

**③ 月亮像太阳。**
夜空用 DOM 画了弯月，光晕给了 `drop-shadow(0 0 14px rgba(255,214,150,.22))` 的暖色强晕，结果渲染出来右上角一个橙色大光斑，比岛还抢眼。改成冷白 `#F1F5FF` + 光晕收到 2.5px/7px 才安静下来。

**④ 清晨等于正午。**
只调色温不改光位，两个时段几乎一样。真正的差异来自**主光高度角**和**雾距**，色温反而是最不重要的一项。

**⑤ 人物放在坡上。**
夏天野餐的孩子按"看起来居中"摆，实际落在坡度为 0.46 的斜坡上，垫子一半悬空。后来写了投影探针，把世界坐标投到屏幕像素，才发现视觉中心和几何中心差了半米。**不要用肉眼估坐标。**

## 十、可复用的检查清单

做同类的「桌面小世界」时，我会按这个顺序检查：

- [ ] 关掉天空盒和地面，它是否还站得住？
- [ ] 缩小到 320px 宽，主体是否还能被认出来？
- [ ] 转到背面，是否有内容，还是一张纸？
- [ ] 有没有一个纯色/纯饱和的地方？那里一定显廉价。
- [ ] 夜里除了"暗"，有没有第二个光源层次？
- [ ] 三个时段各截一张黑白图，明暗关系是否真的不同？
- [ ] 有没有两个东西的动画周期相同？有就错开。
- [ ] 留白是否被植被吃掉了？
